# M02 整合完成与测试说明

日期：2026-10-20。来源固定提交：Mat11-oo/qingyang-health-m02@e12407a93db524cd0cd470f0abbddb3a9c779f44。

## 已合入当前项目

- 今日看板：真实档案、饮水进度、当日体重/BMI；支持日期选择和历史记录。
- 健康档案：目标体重/饮水/热量、可选身高/出生年份/营养目标、目标类型、版本冲突重载；今日和“我的→健康档案”共用一个后端档案。
- 饮水：快捷250ml、手工/历史补录、列表分页、删除；用户行锁下每日6000ml上限；重试幂等。
- 体重：新增、多次记录、历史补录、删除和最新记录回退。
- 大屏：7/30天完整日期网格，体重与饮水图表、记录天数及均值；缺测不会伪造测量。
- M01：保留邮箱注册/登录、资料、上传和通知；M02复用Cookie会话、CSRF、统一客户端、用户隔离、SqlTx和幂等事务。

这次是本地代码整合和配置，不代表线上部署。前后端代码仍各在独立Git仓库；根目录为前端，server/为后端。

## 服务与配置

前端：在项目根目录运行 `npm run dev`，http://127.0.0.1:3001 。

后端：在 server/ 运行 `npm run dev`，http://127.0.0.1:3002/api/v1 。M01上传和通知等异步功能在另一终端运行 `npm run worker`。

前端统一 rewrite 默认连接3002，可用仅服务端变量 API_INTERNAL_URL 调整；不使用原交付 NEXT_PUBLIC_M02_DEV_API 和 A/B测试账号。后端继续使用已有 `.env.local`，没有导入队友密码、数据库或测试账号。真实用户在登录页收取邮箱验证码后使用。

## 未交付模块的处理

饮食/训练/积分/心情/预约端口尚未交付时，后端返回 availability，相关数值为null；前端显示 — 与未接入状态。饮水会保存，但不发积分，不写M05表，也不承诺未来补发。正式端口注册后复用同一事务/快照；真实积分失败会回滚当次饮水。生产原有M05/HTTPS/可信代理检查保持生效。

## 数据库

本次无新增DDL。已只读核实当前开发库迁移记录 V001–V004，以及 health_profiles（14列）、water_records（10列）、weight_records（10列）。M02与现有冻结V001 SHA-256完全一致。线上仍使用 server/db/releases 的统一安装/升级SQL，不重复执行三表参考SQL。
